Spike 002 · Bridge Correlation Addendum

Withdrawal Correlation Must Use withdrawal_index

Correction to the bridge correlation model: withdrawal finalization identity comes from the contract-emitted index, while aux remains a checksum and search field.

Problem

Spike 002 correctly identified that aux is not globally unique. The original FIFO proposal is sufficient for representing duplicate bridge operations, but it is too weak for withdrawal finalization if the finalizer matches by aux, amount, and recipient.

Repeated identical withdrawals can share those values. If an L1 finalization event is correlated to the first pending row with matching aux, the indexer can mark the wrong withdrawal as completed.

For withdrawals, aux must be treated as a checksum and search field, not as the operation identity.

Contract Facts

The bridge contract already emits the discriminator the indexer needs.

zeko/src/app/zeko/circuits/rule_bridge_finalize_withdrawal.ml

  • The finalize proof reconstructs the exact L2 withdrawal action and checks it is connected to the supplied inner action-state extension.
  • next_withdrawal is read from the inner action-state length after that action is pushed.
  • The emitted withdrawal_index is next_withdrawal - 1.
  • The L1 finalize-withdrawal event emits (withdrawal_index, withdrawal_params).

zeko/src/app/zeko/circuits/bridge_state.ml

  • Withdrawal_params_base is { children; amount; recipient }.
  • Withdrawal aux is a hash of the full withdrawal params type, not a unique operation counter.

Therefore, the contract-level identity for a withdrawal is its inner action index, surfaced on L1 as withdrawal_index.

Decision

Use withdrawal_index as the canonical withdrawal correlation key.

(source_network, bridge_instance, withdrawal_index)
  • source_network distinguishes devnet, mainnet, local, and future L1 networks.
  • bridge_instance distinguishes the configured bridge contract/account set.
  • withdrawal_index is the global L2 inner action index for the withdrawal.

The indexer may continue to store (aux, aux_sequence) for generic bridge search, display, compatibility, and duplicate diagnostics. It must not use (aux, aux_sequence) as the primary key for completing withdrawals.

Required Cross-Checks

When the L1 watcher observes a withdrawal finalization, it must decode the finalize-withdrawal event tuple and publish the decoded withdrawalIndex.

Before publishing or before the indexer accepts the event, the pipeline must verify:

  • The decoded withdrawal_params recompute to the OUTER_PK witness aux.
  • The decoded amount matches the indexed L2 withdrawal row.
  • The decoded recipient matches the indexed L2 withdrawal row.
  • The decoded params hash or raw params fields match the indexed L2 evidence.
  • The withdrawalIndex matches the indexed inner_action.action_index.

If any check fails, the indexer must not complete a bridge operation. It should record a degraded or unrecoverable data-quality reason for operator review.

Acceptance Criteria

  • Two identical withdrawals with the same aux are indexed as separate operations.
  • L1 finalization for withdrawal index N completes only withdrawal N.
  • L1 finalization for withdrawal index N + 1 does not complete withdrawal N even when both withdrawals share aux, amount, and recipient.
  • Aux or params mismatch blocks completion and records a data-quality issue.
  • No withdrawal completion path matches by aux alone.
