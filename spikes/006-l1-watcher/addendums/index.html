Implementation Spec

Shared Package, Mina Adapter First

The implementation starts with the shared watcher package and the Zeko-M / Mina adapter. The Ethereum adapter remains behind the same boundary and is implemented in Milestone 4.

Shared Watcher

  • Config validation and process lifecycle.
  • NATS publisher and deterministic message IDs.
  • SurrealDB cursors, canonical block window, published facts.
  • Health endpoint and `zeko.health` publication.

Zeko-M / Mina

  • Mina daemon client for `bestChain`, account reads, and subscriptions.
  • Archive-Node-API clients for actions and zkApp commands.
  • Mina settlement, outer action, bridge, and rollback decoders.

Zeko-E / Ethereum

  • Adapter shell only in Milestone 1.
  • JSON-RPC/archive/log implementation in Milestone 4.
  • Ethereum finality and ABI mappings are later design inputs.
NATS Event Schemas

Provider-Aware L1 Envelope

Shared event subjects remain stable. Payloads carry provider and network metadata so consumers can distinguish Zeko-M / Mina facts from Zeko-E / Ethereum facts. 

type L1Provider = "mina" | "ethereum";
type L1Network =
  | "zeko-m-devnet"
  | "zeko-m-alphanet"
  | "zeko-m-mainnet"
  | "zeko-e-testnet-1"
  | "zeko-e-mainnet";

type L1Envelope = {
  schemaVersion: 1;
  provider: L1Provider;
  network: L1Network;
  source: "l1-watcher";
  observedAt: string;
  block: {
    height: number;
    hash: string;
    parentHash: string;
    slot?: number;
    timestamp?: string;
    confirmationDepth: number;
    providerFields?: Record<string, unknown>;
  };
};

Adapter Interfaces

Common Boundary With Provider Extensions

The common interface is intentionally small. Mina and Ethereum add provider-specific historical reads and decoders outside the shared watcher lifecycle. 

interface L1Adapter {
  readonly provider: "mina" | "ethereum";
  readonly network: L1Network;

  getBestChain(depth: number): Promise<L1BlockRef[]>;
  watchBestChainHints(onHint: () => Promise<void>): Promise<AbortController>;
  getSourceHealth(): Promise<L1SourceHealth>;
}

interface MinaL1Adapter extends L1Adapter {
  readonly provider: "mina";
  readonly network: ZekoMNetwork;

  getAccountState(publicKey: string): Promise<string[]>;
  getOuterActions(input: {
    contractPublicKey: string;
    fromHeight: number;
    toHeight: number;
  }): Promise<MinaArchiveOuterAction[]>;
  getHistoricalZkappCommands(input: {
    fromHeight: number;
    toHeight: number;
  }): Promise<MinaArchiveZkappCommandPage>;
}

interface EthereumL1Adapter extends L1Adapter {
  readonly provider: "ethereum";
  readonly network: ZekoENetwork;

  getSettlementLogs(input: {
    fromBlock: number;
    toBlock: number;
  }): Promise<EthereumLog[]>;
  getBridgeEventLogs(input: {
    fromBlock: number;
    toBlock: number;
  }): Promise<EthereumLog[]>;
}
Fault Tolerance

Failures Degrade Freshness, Not Availability

Runtime dependency failures stay isolated. UI and APIs render available data with source quality metadata instead of blocking unrelated workflows.

FailureWatcher behaviorRecovery
Live L1 endpoint down Pause live tip/finality/reorg work; keep archive catch-up running if possible. Reconnect, reconcile canonical chain window, then resume.
Archive L1 endpoint down Pause historical catch-up; keep live processing running if possible. Resume from durable archive cursor.
NATS down Pause data publication and cursor advancement. Reconnect, retry with deterministic Nats-Msg-Id.
SurrealDB down Pause data facts because cursors/published IDs cannot be persisted. Reload durable state, reconcile, then resume.
Bridge data incomplete Expose data quality metadata. Render partial records and warnings in APIs/UI.
Health limitations: l1_live_unavailable l1_archive_unavailable historical_bridge_events_unavailable bridge_event_gap_unrecoverable helper_cancel_counter_unreconciled nats_unavailable surrealdb_unavailable
Archive-Node-API Requirement

zkappCommands(input) Is Required For Zeko-M Historical Bridge Recovery

The current Archive-Node-API can return OUTER_PK actions. Deposit submissions and cancel deposits need account update details. The Mina adapter needs a range query over successful zkApp commands.

Required field groupWhy it matters
Block identity Height, Mina state hash, optional block hash, global slot, timestamp.
Command identity Transaction hash, status, memo, fee payer, deterministic order.
Account update body Public key, token ID, authorization kind, balance change, call depth.
Raw Mina fields Actions, events, app state, and preconditions as raw field arrays.
Range controls Block range, optional account/token filters, chunking compatible with the archive cap.

After upstream support

Zeko-M deposit, withdrawal, and cancel facts can be rebuilt from historical ranges.

Before upstream support

Watcher downtime outside daemon frontier/NATS retention can leave unrecoverable bridge gaps.

Downstream contract

APIs and UI expose incomplete data explicitly through source status and warnings.
